# AI Panel Studio 开发过程与工作流说明

## 工具与模型

开发记录显示，本项目在 ChatGPT Work Mode 的 Codex 工作区分阶段实施。Codex 读取原始作业、修改仓库文件并通过 PowerShell 运行验证。实际验证工具为 SQLite、pytest、TypeScript/Vite 和 Playwright Chromium。开发助手的精确模型版本，以及是否另用 Claude Code 配合 DeepSeek V4 Pro，现有记录无法确认。**待本人填写**：如确实使用过，请填写工具、模型、实际阶段及可对应的原始记录；如未使用，请据实说明。

应用内模型与开发助手是两套接口。应用通过后端的 OpenAI 兼容适配器调用 Chat Completions，按操作分别请求阵容、意愿、发言、观点与总结。密钥从后端环境变量读取。测试注入固定响应或按场次控制推进的假模型。真实供应商的发言顺序、文本质量和时延本轮缺少配置，未做实测。

## 开发步骤

1. **需求与契约。** 从作业图片提取硬性要求，写成 PRD 的用户路径和验收条件。SDD 阶段先确定数据模型、场次外键、SQLite 约束、SSE 载荷和续接协议，再用空库检验设计。
2. **界面原型。** DDD 阶段实现首页、阵容确认和演播厅，先由模拟事件验证全部路径及响应式布局。模拟和实际接口共享事件应用逻辑，接入真实后端时可复用页面。
3. **核心引擎与集成。** TDD 先让 16 个业务用例明确失败，再补齐阵容、调度、公开数据、观点提炼和总结。后续接入 FastAPI 与持久化，利用条件提交和场次任务管理保证重复确认只触发一次开场。
4. **浏览器验收与回归。** 通过真实按钮操作验证默认阵容、访客加入、两场并行、刷新去重以及窄屏。先单跑问题用例，保留原断言，然后回跑后端、完整 E2E 和构建。

## 三个实际问题

- **离线依赖与本机端口受限。** 注册表无法访问时采用已有缓存恢复验证依赖。沙箱还限制进程连接本机端口，浏览器测试改由 Playwright 把请求转入真实 FastAPI ASGI，并用有限 SSE 窗口覆盖重连。常规网络下的 TCP 验证单独标记。
- **刷新与订阅之间可能出现新事件。** 在同一 SQLite 读事务取快照及游标，订阅只回放后续序号。断线使用最后成功处理的序号，实录按场次和发言 ID 去重。两场同时运行及中途刷新用例验证了这条路径。
- **专家中间状态收到但没画出来。** 初次 E2E 发现三个状态按序到达，但连续渲染更新合并。用前端顺序展示和短暂停留保留可见过渡，同时即时推进接收游标。原失败断言复跑通过。
